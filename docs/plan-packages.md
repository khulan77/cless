# Курс / багц (Package) — B хэсгийн төлөвлөгөө

> Төлөв: **зөвхөн төлөвлөгөө**. Энэ PR-д код, migration ороогүй.
> A12-оор тайланд "Нэг удаагийн үйлчилгээ" ба "Курс/багц" гэж аль хэдийн салгасан. Курсын мөр одоогоор 0 бөгөөд энэ төлөвлөгөө хэрэгжсэний дараа бодит дүн гарна.

## 1. Зорилго

- Үйлчлүүлэгч курсийг (жишээ нь "Нүүрний эмчилгээ × 10") урьдчилж төлж худалдаж авна.
- Тэр курсээ дараа нь цаг бүрт нэг нэгээр ашиглана.
- Үлдэгдэл, хугацаа, буцаалт, шилжүүлгийг систем хөтөлнө.
- Тайлан нь орлогыг **ашигласан үед** таньдаг (deferred revenue). Худалдах үед мөнгөн орлого бүртгэгдэнэ.
- Тайлан "Курс/багц" мөрөнд ашигласан хэсгийн үнийг харуулна.

## 2. Загвар (Prisma, нэмэлт migration)

```prisma
/// Худалдах курсын загвар (админ тохируулна)
model Package {
  id           String   @id @default(cuid())
  name         String
  /// Багцад орох үйлчилгээ ба тоо. Ихэвчлэн 1 үйлчилгээ; олон үйлчилгээ ч болно
  items        PackageItem[]
  price        Int                // багцын үнэ (₮)
  validDays    Int?               // худалдсанаас хойш хүчинтэй хоног (null = хугацаагүй)
  isActive     Boolean  @default(true)
  slItemId     String?            // Smart Logic-ийн бараа (дараа)
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}

model PackageItem {
  id         String  @id @default(cuid())
  packageId  String
  serviceId  String
  sessions   Int                  // энэ үйлчилгээний хэдэн удаа
}

/// Үйлчлүүлэгчийн худалдаж авсан курс
model CustomerPackage {
  id            String   @id @default(cuid())
  customerId    String
  packageId     String
  saleItemId    String   @unique  // худалдсан POS-ийн мөр (SaleItem.kind = PACKAGE)
  paidAmount    Int                // бодит төлсөн дүн (хөнгөлөлтийн дараа)
  totalSessions Int
  usedSessions  Int      @default(0)   // КЭШ: Σ PackageRedemption (буцаагдаагүй)
  expiresAt     DateTime?
  status        CustomerPackageStatus @default(ACTIVE) // ACTIVE | USED_UP | EXPIRED | REFUNDED | TRANSFERRED
  transferredFromId String?        // шилжүүлсэн бол эх курс
  createdAt     DateTime @default(now())
}

/// Нэг удаагийн ашиглалт (цаг DONE болоход эсвэл POS-оос)
model PackageRedemption {
  id                String   @id @default(cuid())
  customerPackageId String
  appointmentId     String?  @unique
  serviceId         String
  staffId           String?           // урамшуулал, "Миний борлуулалт"
  /// Ашигласан үеийн нэг удаагийн үнэ = paidAmount / totalSessions (сүүлийнх нь үлдэгдлийг авна)
  unitValue         Int
  reversedAt        DateTime?         // цаг буцаагдсан/алдаатай бол (устгахгүй)
  createdById       String
  createdAt         DateTime @default(now())
}
```

- `SaleItem.kind`-д `PACKAGE` утга нэмнэ (enum-д нэмэлт).
- Багц худалдах нь одоогийн POS мөрийн урсгалаар явна: хөнгөлөлт, төлбөр, буцаалт хэвээр ажиллана.
- Нэг үйлчлүүлэгч нэг курсыг давхар ашиглахаас `SELECT … FOR UPDATE` хамгаална. Энэ нь цагийн overlap constraint-тай ижил зарчим.

## 3. Нэг удаагийн үнэ

`unitValue = floor(paidAmount / totalSessions)`, **сүүлийн удаа** үлдэгдлийг авна. Ингэснээр нийлбэр нь `paidAmount`-тай яг тэнцэнэ. Энэ нь `refundLineAmount`-ийн дүрэмтэй ижил.

Жишээ: 10 удаа, 1 000 000₮, 10% хөнгөлөлттэй.

- `paidAmount` = 900 000.
- Нэг удаа = 90 000.
- Тайлангийн "Курс/багц" мөрөнд ашиглах бүрт 90 000 нэмэгдэнэ.
- Гоо сайханчийн урамшуулал нь энэ 90 000-аас бодогдоно. Одоогийн `commissionFor` дүрэмтэй, `kind = SERVICE`.

## 4. Тохиолдлууд

| Тохиолдол | Шийдэл |
|---|---|
| **Цаг цуцлагдсан / ирээгүй** | Redemption үүсэхгүй. Ашиглалт зөвхөн DONE үед бүртгэгдэнэ. Хэрэв NO_SHOW-г "шатаах" бодлого байвал тохиргоогоор асаана. Default нь шатаахгүй. |
| **DONE-г буцаасан** (алдаатай тэмдэглэсэн) | `reversedAt` тавьж, `usedSessions`-ийг буурулна. Мөрийг устгахгүй, AuditLog бичнэ. |
| **Курс буцаах** (үйлчлүүлэгч болиулсан) | Буцаах дүн = `paidAmount − Σ unitValue(ашигласан)`. Энэ нь одоогийн Refund урсгалаар SaleItem (PACKAGE)-ийн хэсэгчилсэн дүнгээр явна. Status `REFUNDED` болно. Цуцлалтын хураамж (жишээ нь 10%) тохиргоогоор. |
| **Хугацаа дууссан** | Шөнийн worker job `EXPIRED` болгоно. Үлдсэн удаа ашиглагдахгүй. Нягтлан бодох бүртгэлд үлдэгдэл нь "хугацаа дууссан орлого" болж тайланд тусдаа мөрөнд гарна. Менежер хугацааг сунгаж болно (AuditLog). |
| **Шилжүүлэх** (өөр үйлчлүүлэгчид) | Шинэ `CustomerPackage` үүснэ: үлдсэн удаа, үлдсэн дүн, `transferredFromId`. Хуучин нь `TRANSFERRED` болно. Зөвхөн MANAGER/ADMIN. |
| **Үнэ өөрчлөгдсөн** | Хуучин курс худалдсан үеийн `paidAmount`-оор үргэлжилнэ, нөлөөгүй. |
| **Өөр үйлчилгээ** (багцад ороогүй) | Ашиглах боломжгүй. Тухайн цагт POS-оор ердийн төлбөр авна. |

## 5. Тайлан

- **Нэг удаагийн үйлчилгээ**: одоогийнхтой ижил SaleItem SERVICE.
- **Курс/багц** (A12-ийн мөр): Σ `PackageRedemption.unitValue` (буцаагдаагүй), `createdAt` нь сонгосон хугацаанд.
- **Курс худалдсан мөнгө**: SaleItem PACKAGE, тусдаа мөр. Мөнгөн орлого бөгөөд "Нийт орлого"-д давхар тоологдохгүй.
- **Ашиглагдаагүй үлдэгдэл** (deferred): Σ ACTIVE курсын `paidAmount − ашигласан`. Нягтлан энэ дүнг хүсэх магадлалтай, тиймээс "Нягтланд илгээх" Excel-д нэмнэ.
- Product analytics (A10): курсын үйлчилгээ DONE болоход ServiceConsumable-ийн зарцуулалт хэвээр тоологдоно. Өөрчлөлт хэрэггүй.

## 6. eBarimt / Smart Logic

| Сонголт | Давуу | Сул |
|---|---|---|
| **А. Худалдах үед бүтэн дүнгээр баримт** (санал болгож буй) | Мөнгө орж ирэхэд баримт гарна. Одоогийн POS → EbarimtReceipt урсгал хэвээр. Хэрэгжүүлэхэд хамгийн хялбар. | Буцаалтад хэсэгчилсэн буцаалтын баримт хэрэгтэй. Энэ нь одоогийн refund урсгалд аль хэдийн бий. |
| Б. Ашиглах бүрт баримт | Баримт нь үйлчилгээ үзүүлсэнтэй таарна. | Мөнгө авсан үед баримт гаргахгүй, татварын хувьд эрсдэлтэй. 0₮-ийн POS мөр шаардлагатай. Цаг бүрт eBarimt дуудлага хийнэ. |
| В. Урьдчилгаа + ашиглах үед хаах | Нягтлан бодох бүртгэлд хамгийн цэвэр. | eBarimt-д урьдчилгааны төрөл хэрэгтэй. Нягтлантай тохирох шаардлагатай, хамгийн их ажил. |

**Smart Logic**:
- `Package.slItemId`-аар курсыг бараа болгон холбоно.
- Худалдсан мөрийг SL руу илгээнэ: "А" хувилбартай ижил цэг, нэг удаа.
- Ашиглалтыг SL руу илгээхгүй. Нөөц хөдлөхгүй, ServiceConsumable зөвхөн манай системд.
- **Нээлттэй асуулт (нягтлан + SL-ийн хариуцагчаас):** SL нь урьдчилгааны (deferred) дансыг дэмжих үү?

## 7. Wallet / GiftCard-ыг дахин ашиглах эсэх

- Wallet нь **мөнгөн** үлдэгдэл (₮). Курс нь **удаагийн** үлдэгдэл (× удаа). Тиймээс нэг загварт шахвал тайлан, урамшуулал, хугацааны логик бүдгэрнэ.
- Иймээс курс **тусдаа** загвар (`CustomerPackage`) байна.
- Дараах хэсгүүдийг дахин ашиглана:
  - Wallet-ийн "КЭШ + ledger" зарчим (`balance` ↔ Σ `WalletTxn`), энд `usedSessions` ↔ Σ `PackageRedemption`;
  - GiftCard-ийн `expiresAt` + шөнийн job;
  - Refund урсгал (хэсэгчилсэн дүн, AuditLog).
- Курс буцаахад үлдэгдлийг бэлнээр биш **хэтэвч рүү** (Wallet) шилжүүлэх сонголт өгч болно. Энэ нь одоогийн WalletTxn-ийг шууд ашиглана.

## 8. UI (товч)

- **Үйлчилгээ → Курс/багц**: жагсаалт, үүсгэх (үйлчилгээ × удаа, үнэ, хугацаа).
- **POS**: каталогт курс харагдана, худалдахад үйлчлүүлэгч заавал сонгоно.
- **Календарь / цагийн самбар**: үйлчлүүлэгчид тохирох идэвхтэй курс байвал "Курсээс ашиглах (3/10 үлдсэн)" гэсэн сонголт гарна. DONE болоход Redemption үүснэ.
- **Үйлчлүүлэгчийн дэлгэрэнгүй**: шинэ таб "Курс". Үлдэгдэл, түүх, буцаах, шилжүүлэх, хугацаа сунгах товчнууд энд байна.
- **Миний самбар** (STAFF): курсын ашиглалт "Миний борлуулалт"-д `unitValue`-ээр гарна.
- **Тайлан**: A12-ийн "Курс/багц" мөр бодит болно. Мөн "Курс худалдсан", "Ашиглагдаагүй үлдэгдэл" картууд нэмэгдэнэ.

## 9. Эрх (permissions.ts)

- `package:write`: курсын загвар үүсгэх. ADMIN, MANAGER.
- `package:redeem`: цагт курс ашиглах. ADMIN, MANAGER, ресепшн. STAFF нь зөвхөн өөрийн цагт эрхтэй байх эсэхийг шийднэ.
- `package:adjust`: буцаах, шилжүүлэх, хугацаа сунгах. ADMIN, MANAGER.
- Бүгд `guards.test.ts`-ийн автомат шалгалтад орно.

## 10. Ажлын хэмжээ (тооцоо)

| Ажил | Өдөр |
|---|---|
| Migration + загвар + service (худалдах, ашиглах, буцаах, шилжүүлэх, хугацаа) | 2 |
| DB тестүүд (давхар ашиглалт, нийлбэр = paidAmount, буцаалт, хугацаа) | 1 |
| POS + цагийн самбар (ашиглах) | 1.5 |
| Үйлчлүүлэгчийн "Курс" таб + админы курсын жагсаалт | 1 |
| Тайлан (A12 мөр, deferred, Excel/нягтлан) + урамшуулал | 1 |
| eBarimt ("А" хувилбар) шалгалт, refund-ийн баримт | 0.5 |
| E2E + гарын авлага (сургалтад) | 1 |
| **Нийт** | **≈ 8 ажлын өдөр** |

Хэрэв "Б"/"В" eBarimt хувилбар эсвэл SL-ийн deferred данс шаардвал **+2–3 өдөр** нэмэгдэнэ.
